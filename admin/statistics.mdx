## Total Media Count

The most basic metric: total number of media items in the catalog.

```sql
SELECT COUNT(*) as total FROM media_items
```

## Content by Publication Year

Historical distribution of media items based on their publication year.

### Query

```sql
SELECT publication_year, COUNT(*) as total
FROM media_items
WHERE publication_year IS NOT NULL
GROUP BY publication_year
ORDER BY publication_year DESC
```

## Storage Statistics

Comprehensive disk usage metrics including file sizes, available space, and utilization percentages.

### Storage Calculation Process

<Steps>
  <Step title="Calculate Total File Size">
    The system scans all media items and sums their file sizes:
    
    ```javascript
    const [files] = await connection.promise().query(
        "SELECT media_path FROM media_items"
    );

    let totalBytes = 0;
    for (const file of files) {
        if (fs.existsSync(file.media_path)) {
            const stats = fs.statSync(file.media_path);
            totalBytes += stats.size;
        }
    }
    ```
    
    See `/home/daytona/workspace/source/api/main.js:623-632`.
  </Step>
  
  <Step title="Query Disk Statistics (Linux/macOS)">
    On Unix-based systems, the `df` command retrieves partition information:
    
    ```javascript
    const dfOutput = execSync(`df -k "${mediaPath}"`).toString();
    const lines = dfOutput.trim().split('\n');
    const stats = lines[1].split(/\s+/);
    const blockSize = 1024;

    diskStats = {
        total: parseInt(stats[1]) * blockSize,    // Total partition size
        used: parseInt(stats[2]) * blockSize,     // Used space
        free: parseInt(stats[3]) * blockSize,     // Available space
        usedPercentage: (parseInt(stats[2]) / parseInt(stats[1])) * 100
    };
    ```
    
    See `/home/daytona/workspace/source/api/main.js:636-652`.
  </Step>
  
  <Step title="Format Human-Readable Sizes">
    The `formatBytes()` helper converts bytes to KB, MB, GB, etc.:
    
    ```javascript
    function formatBytes(bytes, decimals = 2) {
        if (bytes === 0) return '0 Bytes';
        
        const k = 1024;
        const sizes = ['Bytes', 'KB', 'MB', 'GB', 'TB'];
        const i = Math.floor(Math.log(bytes) / Math.log(k));
        
        return parseFloat((bytes / Math.pow(k, i)).toFixed(decimals)) + ' ' + sizes[i];
    }
    ```
    
    See `/home/daytona/workspace/source/api/main.js:1014-1024`.
  </Step>
</Steps>

### Storage Metrics Explained

<AccordionGroup>
  <Accordion title="bytes" icon="file">
    **Total size of all media files** tracked in the `media_items` table.
    
    - Calculated by summing `fs.statSync(media_path).size` for all items
    - Excludes thumbnails, database size, and other system files
    - Only counts files that exist on disk
  </Accordion>
  
  <Accordion title="formatted" icon="text">
    **Human-readable representation** of the `bytes` value.
    
    Examples:
    - `"487.82 GB"`
    - `"3.45 TB"`
    - `"128.30 MB"`
    
    Uses 2 decimal places by default.
  </Accordion>
  
  <Accordion title="total" icon="hard-drive">
    **Total capacity of the storage partition** where `MEDIA_PATH` is located.
    
    - Retrieved from `df` command (Linux/macOS)
    - Represents entire partition size, not just media directory
    - Value in bytes
  </Accordion>
  
  <Accordion title="free" icon="circle-check">
    **Available space** remaining on the storage partition.
    
    - Retrieved from `df` command
    - Shared with other applications on the same partition
    - Use to determine if there's room for new uploads
  </Accordion>
  
  <Accordion title="usedPercentage" icon="percent">
    **Percentage of partition capacity currently in use** (all files, not just media).
    
    Calculation: `(used / total) * 100`
    
    <Warning>
      Values above 90% indicate the partition is nearly full. Consider:
      - Adding more storage capacity
      - Archiving old content
      - Creating a new storage location on a different partition
    </Warning>
  </Accordion>
</AccordionGroup>

## Platform Compatibility

### Linux and macOS

✅ Full storage statistics available

The `df` command is used to query partition information:

```bash
df -k "/path/to/media"
```

### Windows

⚠️ Limited storage statistics

The current implementation checks `process.platform === 'linux' || process.platform === 'darwin'` before running disk queries. On Windows:

- `bytes` and `formatted` will still be calculated (file sizes)
- `total`, `free`, and `usedPercentage` will be `0` or unavailable

<Info>
  **Windows Enhancement**: To support Windows, the `df` command could be replaced with PowerShell's `Get-PSDrive` or the `diskusage` npm package.
</Info>

## Error Handling

The statistics endpoint includes robust error handling:

```javascript
try {
    // Calculate storage
} catch (diskError) {
    console.error('Error obteniendo estadísticas del disco:', diskError);
    // Continue with default values
}
```

If disk statistics fail:
- The request still succeeds
- Storage fields default to `0`
- Error is logged server-side
- Other statistics (counts, types, years) are unaffected

## Frontend Dashboard Integration

Example of fetching and displaying statistics:

```javascript
fetch('/api/stats', {
  headers: {
    'Authorization': `Bearer ${token}`
  }
})
.then(res => res.json())
.then(data => {
  if (data.success) {
    const { total, byType, byYear, storage } = data.stats;
    
    // Display total count
    document.getElementById('total-items').textContent = total;
    
    // Render type distribution chart
    renderPieChart('type-chart', byType);
    
    // Render year timeline
    renderBarChart('year-chart', byYear);
    
    // Display storage info
    document.getElementById('storage-used').textContent = storage.formatted;
    document.getElementById('storage-percentage').textContent = 
      `${storage.usedPercentage.toFixed(1)}%`;
    
    // Storage warning
    if (storage.usedPercentage > 90) {
      showStorageWarning();
    }
  }
})
.catch(err => console.error('Failed to load statistics:', err));
```

## Performance Considerations

### File System Scanning

The storage calculation requires:
- Database query to fetch all `media_path` values
- `fs.existsSync()` check for each file
- `fs.statSync()` to read file size

<Warning>
  **Large Catalogs**: For archives with thousands of files, this operation may take several seconds. Consider:
  
  - Caching statistics (refresh every 5-15 minutes)
  - Computing statistics asynchronously in the background
  - Storing file sizes in the database during upload to avoid disk scans
</Warning>

### Database Queries

The endpoint executes three separate queries:
1. Total count
2. Group by media type
3. Group by publication year

These are relatively fast, but adding database indexes can improve performance:

```sql
CREATE INDEX idx_media_type ON media_items(media_type_id);
CREATE INDEX idx_pub_year ON media_items(publication_year);
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Storage Shows 0 Bytes">
    Possible causes:
    - No media items in database
    - Files have been deleted but database records remain
    - Permission issues preventing `fs.statSync()`
    
    **Solution**: 
    1. Verify media items exist: `SELECT COUNT(*) FROM media_items`
    2. Check file permissions
    3. Verify `media_path` values are correct
  </Accordion>
  
  <Accordion title="Disk Statistics Unavailable on Windows">
    The current implementation only supports Linux and macOS for disk queries.
    
    **Solution**: Implement Windows support using PowerShell or a cross-platform library like `diskusage`.
  </Accordion>
  
  <Accordion title="Statistics Load Slowly">
    Large media catalogs can take time to scan.
    
    **Solution**:
    - Implement caching (Redis or in-memory)
    - Store file sizes in database during upload
    - Use pagination for year/type breakdowns
  </Accordion>
  
  <Accordion title="403 Forbidden Error">
    All authenticated users can access statistics, but the token may be invalid or expired.
    
    **Solution**: Verify token with `GET /api/user/role`
  </Accordion>
</AccordionGroup>
