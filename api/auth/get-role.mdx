## GET /api/user/role

Retrieves the authenticated user's role and associated permissions. This endpoint is used by the frontend to determine what UI elements and actions to display based on the user's role.

## Authentication

<Note>
This endpoint requires authentication. Include a valid JWT token in the Authorization header.
</Note>

```bash
Authorization: Bearer <token>
```

## Response

<ResponseField name="success" type="boolean">
  Indicates if the request was successful
</ResponseField>

<ResponseField name="user" type="object">
  User information object
  
  <Expandable title="properties">
    <ResponseField name="id_user" type="integer">
      User's unique identifier
    </ResponseField>
    
    <ResponseField name="nombre" type="string">
      Username
    </ResponseField>
    
    <ResponseField name="rol" type="string">
      User's role: `admin`, `moderator`, or `viewer`
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="permissions" type="object">
  Permissions object based on user role
  
  <Expandable title="properties">
    <ResponseField name="canUpload" type="boolean">
      Whether user can upload media files
    </ResponseField>
    
    <ResponseField name="canDelete" type="boolean">
      Whether user can delete media files
    </ResponseField>
    
    <ResponseField name="canEdit" type="boolean">
      Whether user can edit media metadata
    </ResponseField>
    
    <ResponseField name="canDownload" type="boolean">
      Whether user can download media files
    </ResponseField>
    
    <ResponseField name="canManageUsers" type="boolean">
      Whether user can manage other users
    </ResponseField>
    
    <ResponseField name="canViewAllContent" type="boolean">
      Whether user can view all media content
    </ResponseField>
    
    <ResponseField name="role" type="string">
      Role name (same as user.rol)
    </ResponseField>
    
    <ResponseField name="level" type="integer">
      Permission level: 3 (admin), 2 (moderator), 1 (viewer)
    </ResponseField>
  </Expandable>
</ResponseField>

## Implementation Details

The endpoint implementation from `api/main.js:494-514`:

```javascript
app.get('/api/user/role', verifyToken, async (req, res) => {
    try {
        const [rows] = await connection.promise().query(
            "SELECT id_user, nombre, rol FROM users WHERE id_user = ?",
            [req.user.id_user]
        );

        if (rows.length === 0) {
            return res.status(404).json({ error: "Usuario no encontrado" });
        }

        res.json({
            success: true,
            user: rows[0],
            permissions: getPermissionsByRole(rows[0].rol)
        });

    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});
```

The `getPermissionsByRole()` helper function maps each role to its permission set (source: `api/main.js:516-551`).

- **Client-side validation**: Validate user capabilities before attempting protected operations
