## Overview

This endpoint retrieves complete details for a single media item, including all metadata, associated authors with their roles, media type, and storage location information.

## Authentication

Requires JWT token via `Authorization: Bearer <token>` header.

## Path Parameters

<ParamField path="id" type="integer" required>
  The unique identifier of the media item to retrieve
</ParamField>

## SQL Query

```sql
SELECT 
    m.*,
    ct.name AS media_type,
    ml.path AS location_path,
    GROUP_CONCAT(DISTINCT a.id_user) AS author_ids,
    GROUP_CONCAT(DISTINCT a.nombre) AS author_names,
    GROUP_CONCAT(DISTINCT a.role) AS author_roles
FROM media_items m
LEFT JOIN media_types ct ON m.media_type_id = ct.id
LEFT JOIN media_locations ml ON m.media_location_id = ml.id
LEFT JOIN media_author ma ON m.id = ma.media_id
LEFT JOIN users a ON ma.user_id = a.id_user
WHERE m.id = ?
GROUP BY m.id
```

## Author Processing

The endpoint performs special processing for author data:

1. **Data Aggregation**: Uses `GROUP_CONCAT` to collect author IDs, names, and roles
2. **String Splitting**: Splits comma-separated values into arrays
3. **Object Construction**: Builds structured author objects with id, name, and role
4. **Field Cleanup**: Removes raw concatenated fields from the response

## Use Cases

- **Detail View**: Display full information on a media detail page
- **Edit Form**: Pre-populate form fields when editing media
- **Metadata Extraction**: Extract information for reports or analytics
- **Verification**: Confirm media item details before operations

## Implementation Notes

- All fields from the `media_items` table are included via `m.*`
- The `GROUP BY m.id` ensures proper aggregation with LEFT JOINs
- Author roles are fetched from the `users` table, not the junction table
- Empty author arrays are returned for media items with no associated authors
