## Overview

This endpoint allows authorized users to update the metadata of an existing media item, including title, description, publication year, media type, tags, and associated authors. Note that the actual file cannot be replaced through this endpoint.

## Authentication

Requires JWT token via `Authorization: Bearer <token>` header.

### Permission Requirements

- **Viewers**: Cannot update content (403 Forbidden)
- **Moderators**: Can update content
- **Admins**: Can update content

## SQL Queries

### Update Media Item

```sql
UPDATE media_items 
SET title = ?, 
    description = ?, 
    publication_year = ?, 
    media_type_id = ?, 
    tags = ?,
    date_updated = CURRENT_TIMESTAMP
WHERE id = ?
```

### Replace Author Associations

**Delete existing associations:**
```sql
DELETE FROM media_author WHERE media_id = ?
```

**Insert new associations:**
```sql
INSERT INTO media_author (media_id, user_id) VALUES (?, ?)
```

## Example Request (JSON)

```bash
curl -X PUT https://api.example.com/api/files/42 \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
```

## Error Responses

### 403 Forbidden (Insufficient Permissions)
```json
{
  "error": "No tienes permisos"
}
```
Returned when a viewer role attempts to update content.

### 401 Unauthorized
```json
{
  "error": "Token requerido"
}
```
Returned when no authentication token is provided.

### 404 Not Found
No explicit error is returned if the media item doesn't exist. The operation will complete with `success: true` but affect 0 rows. To verify existence, use `GET /api/files/:id` before updating.

### 500 Internal Server Error
```json
{
  "error": "Foreign key constraint fails"
}
```
Returned when invalid references are provided (e.g., non-existent author_ids or media_type_id).

## Update Behavior

### Timestamp Update

- The `date_updated` field is automatically set to `CURRENT_TIMESTAMP` on every update
- The `date_added` field remains unchanged

### Author Replacement

The author update process is **destructive**:

1. **All existing author associations are deleted**
2. **New associations are inserted based on `author_ids`**
3. If `author_ids` is not provided, existing associations remain unchanged
4. If `author_ids` is an empty array, all author associations are removed

### Partial Updates

The endpoint does not support partial updates. All fields (title, description, publication_year, media_type_id, tags) must be provided in each request, even if only one field has changed.

## What Cannot Be Updated

- **File itself**: The physical media file cannot be replaced
- **File path**: The `media_path` and `filename` fields are immutable
- **Storage location**: The `media_location_id` cannot be changed
- **Creation date**: The `date_added` timestamp is preserved
- **Media ID**: The primary key cannot be modified

## Implementation Notes

- The endpoint accepts both `application/json` and `multipart/form-data` content types
- Multer middleware is configured but doesn't expect a file in this endpoint
- The `author_ids` field can be passed as either a JSON array or a JSON string
- All database operations are performed sequentially, not in a transaction
- No rollback occurs if author insertion fails after the main update succeeds

## Best Practices

1. **Fetch before update**: Use `GET /api/files/:id` to retrieve current values
2. **Preserve unchanged fields**: Include all fields even if only updating one
3. **Validate author IDs**: Ensure all author IDs exist before sending the request
4. **Handle errors gracefully**: Check for 500 errors indicating constraint violations
