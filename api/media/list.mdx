## Overview

This API provides two endpoints for listing media files:

1. **GET /api/files** - Simple filtered list of all media
2. **GET /api/files/paginated** - Paginated list with advanced sorting

Both endpoints require authentication and return media items with associated metadata, authors, and type information.

---

## GET /api/files

Retrieve all media files matching the specified filters.

### Authentication

Requires JWT token via `Authorization: Bearer <token>` header.

### Query Parameters

<ParamField query="search" type="string">
  Search term to filter by title, description, or tags (partial match)
</ParamField>

<ParamField query="media_type" type="string">
  Filter by media type name (exact match)
</ParamField>

<ParamField query="author" type="string">
  Filter by author name (partial match)
</ParamField>

### SQL Query

```sql
SELECT 
    m.id,
    m.title,
    m.description,
    m.publication_year,
    m.media_path,
    m.filename,
    m.tags,
    m.date_added,
    m.date_updated,
    ct.name AS media_type,
    ml.path AS location_path,
    GROUP_CONCAT(DISTINCT a.nombre) AS authors,
    GROUP_CONCAT(DISTINCT a.id_user) AS author_ids
FROM media_items m
LEFT JOIN media_types ct ON m.media_type_id = ct.id
LEFT JOIN media_locations ml ON m.media_location_id = ml.id
LEFT JOIN media_author ma ON m.id = ma.media_id
LEFT JOIN users a ON ma.user_id = a.id_user
WHERE 1=1
  AND (m.title LIKE ? OR m.description LIKE ? OR m.tags LIKE ?)
  AND ct.name = ?
  AND a.nombre LIKE ?
GROUP BY m.id 
ORDER BY m.date_added DESC
```

### Response

Returns an array of media items.

<ResponseField name="id" type="integer">
  Unique identifier for the media item
</ResponseField>

<ResponseField name="title" type="string">
  Title of the media
</ResponseField>

<ResponseField name="description" type="string">
  Description of the content
</ResponseField>

<ResponseField name="publication_year" type="integer">
  Year of publication
</ResponseField>

<ResponseField name="media_path" type="string">
  Full file system path to the media file
</ResponseField>

<ResponseField name="filename" type="string">
  Name of the file with timestamp prefix
</ResponseField>

<ResponseField name="tags" type="string">
  Comma-separated tags
</ResponseField>

<ResponseField name="date_added" type="datetime">
  Timestamp when the media was uploaded
</ResponseField>

<ResponseField name="date_updated" type="datetime">
  Timestamp of last update
</ResponseField>

<ResponseField name="media_type" type="string">
  Name of the media type category
</ResponseField>

<ResponseField name="location_path" type="string">
  Base storage location path
</ResponseField>

<ResponseField name="authors" type="array">
  Array of author names associated with this media
</ResponseField>

<ResponseField name="author_ids" type="array">
  Array of author user IDs
</ResponseField>

## GET /api/files/paginated

Retrieve media files with pagination and advanced sorting options.

### Authentication

Requires JWT token via `Authorization: Bearer <token>` header.

### Query Parameters

<ParamField query="page" type="integer" default="1">
  Page number (1-indexed)
</ParamField>

<ParamField query="limit" type="integer" default="10">
  Number of items per page
</ParamField>

<ParamField query="search" type="string" default="">
  Search term to filter by title, description, or tags
</ParamField>

<ParamField query="order" type="string" default="masReciente">
  Sort order. Options:
  - `masReciente` - Most recent by publication year and date added (DESC)
  - `masAntiguo` - Oldest by publication year and date added (ASC)
  - `nombreAZ` - Title A-Z
  - `nombreZA` - Title Z-A
</ParamField>

<ParamField query="type" type="integer" default="0">
  Filter by media type ID. Use `0` for all types.
</ParamField>

### SQL Query

```sql
SELECT 
    m.*,
    ct.name AS media_type,
    ml.path AS location_path,
    GROUP_CONCAT(DISTINCT a.nombre) AS authors,
    GROUP_CONCAT(DISTINCT a.id_user) AS author_ids
FROM media_items m
LEFT JOIN media_types ct ON m.media_type_id = ct.id
LEFT JOIN media_locations ml ON m.media_location_id = ml.id
LEFT JOIN media_author ma ON m.id = ma.media_id
LEFT JOIN users a ON ma.user_id = a.id_user
WHERE (m.title LIKE ? OR m.description LIKE ? OR m.tags LIKE ?)
  AND m.media_type_id = ?
GROUP BY m.id
ORDER BY {dynamic_order}
LIMIT ? OFFSET ?
```

**Count query for pagination:**
```sql
SELECT COUNT(*) as total FROM media_items
```

### Response

<ResponseField name="success" type="boolean">
  Indicates successful retrieval
</ResponseField>

<ResponseField name="data" type="array">
  Array of media items (same structure as `/api/files`)
</ResponseField>

<ResponseField name="pagination" type="object">
  Pagination metadata
  
  <ResponseField name="pagination.page" type="integer">
    Current page number
  </ResponseField>
  
  <ResponseField name="pagination.limit" type="integer">
    Items per page
  </ResponseField>
  
  <ResponseField name="pagination.total" type="integer">
    Total number of media items in the database
  </ResponseField>
  
  <ResponseField name="pagination.pages" type="integer">
    Total number of pages
  </ResponseField>
</ResponseField>

### Example Request

```bash
curl -X GET "https://api.example.com/api/files/paginated?page=2&limit=20&order=nombreAZ&type=1&search=interview" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

## Implementation Notes

- Both endpoints use `GROUP_CONCAT` to aggregate multiple authors into comma-separated lists
- Author names and IDs are split into arrays in the response processing
- The paginated endpoint calculates offset as `(page - 1) * limit`
- When `type=0`, the media type filter is not applied
- Search is performed with `LIKE` queries using `%search%` pattern
