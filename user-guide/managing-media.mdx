## Overview

Once media files are uploaded, users can view details, download files, edit metadata, and delete content based on their role permissions. This guide covers all media management operations.

## Media Grid Display

The main page displays media files in a responsive grid layout (`front/src/components/file-grid/file-grid.component.ts:16-54`).

### Grid Features

- **Card-based layout** - Each file is displayed as a card
- **Thumbnail preview** - Visual preview of images and videos
- **Metadata display** - Title, description, tags, dates
- **Action buttons** - Download, edit, delete (based on permissions)
- **Infinite scroll** - Loads 20 files at a time

<Info>
The grid uses the **Intersection Observer API** to automatically load more files as you scroll down.
</Info>

## Thumbnails

The system automatically generates and displays thumbnails for different media types.

### Thumbnail Generation

Thumbnail URLs are generated by `getThumbnailUrl()` (`front/src/services/file.service.ts:140-152`):

```typescript
getThumbnailUrl(media: MediaItem): string {
  switch (this.getType(media.filename)) {
    case "video":
      return `${this.API}/files/${media.id}/thumbnail`;
    
    case "image":
      return `${this.API}/files/${media.id}/download`;
    
    default:
      return `https://placehold.net/shape-600x600.png`;
  }
}
```

### Thumbnail Types

- **Videos**: Server-generated thumbnail from `/api/files/{id}/thumbnail`
- **Images**: Original image from `/api/files/{id}/download`
- **Other files**: Placeholder image from placehold.net

### Content Type Icons

Each file type displays a unique icon badge (`front/src/services/file.service.ts:117-124`):

- **Video** - Purple badge with video camera icon
- **Image** - Orange badge with image icon
- **Audio** - Green badge with music note icon
- **Document** - Indigo badge with file icon
- **Other** - Gray badge with generic file icon

## Downloading Media

Users with the **`canDownload`** permission can download files.

### Download Button

```html
<button *ngIf="canDownloadContent" 
        (click)="onDownload($event)" 
        title="Descargar">
  <svg><!-- Download icon --></svg>
</button>
```

### Download Process

The download handler (`front/src/components/file-grid/file-grid.component.ts:212-224`):

```typescript
onDownload(file: MediaItem) {
  this.fileService.downloadMedia(file.id).subscribe({
    next: (blob) => {
      const url = window.URL.createObjectURL(blob);
      const a = document.createElement('a');
      a.href = url;
      a.download = file.title;  // Downloaded with title as filename
      a.click();
      window.URL.revokeObjectURL(url);  // Clean up memory
    },
    error: (error) => console.error('Error downloading:', error)
  });
}
```

### Download API

Files are downloaded from `/api/files/{id}/download` as a binary blob (`front/src/services/file.service.ts:79-87`):

```typescript
downloadMedia(id: number): Observable<Blob> {
  return this.http.get(
    `${this.API}/files/${id}/download`,
    {
      headers: this.getHeaders(),
      responseType: 'blob'  // Binary response
    }
  );
}
```

<Info>
Downloaded files are saved with the **media title** as the filename, not the original filename.
</Info>

## Editing Media

Users with the **`canEdit`** permission can modify media metadata.

### Edit Button

```html

        (click)="onEdit($event)" 
        title="Editar">
  <svg><!-- Edit pencil icon --></svg>

```

### Opening the Edit Modal

The edit handler (`front/src/components/file-grid/file-grid.component.ts:226-246`) opens a modal pre-filled with existing data:

```typescript
onEdit(file: MediaItem) {
  this.modalService.open(ContentModalComponent, {
    title: 'Editar Archivo',
    data: {
      confirmText: 'Guardar Cambios',
      cancelText: 'Cancelar Cambios',
      id: file.id,
      title: file.title,
      description: file.description,
      publicationYear: file.publication_year,
      selectedTypeId: file.media_type_id,
      storageLocationId: file.media_location_id,
      tags: file.tags?.split(','),
      currentFileName: file.filename,
      onSubmit: () => {
        window.location.reload();
      }
    }
  });
}
```

### Editable Fields

You can edit all metadata fields:
- **File** (optional) - Replace the file
- **Content type** - Change the media category
- **Title** - Update the display title
- **Description** - Modify the description
- **Publication year** - Change the year
- **Storage location** - Move to a different folder
- **Tags** - Add, remove, or modify tags

<Note>
If you don't select a new file, the original file is preserved and only metadata is updated.
</Note>

## Deleting Media

Users with the **`canDelete`** permission can permanently remove files.

### Delete Button

```html
<button *ngIf="canDeleteContent" 
        (click)="onDelete($event)" 
        title="Eliminar" 
        class="action-btn delete">
  <svg><!-- Trash icon --></svg>
</button>
```

### Confirmation Modal

Before deletion, a confirmation modal appears (`front/src/components/file-grid/file-grid.component.ts:248-270`):

```typescript
onDelete(file: MediaItem) {
  this.modalService.open(ConfirmationModalComponent, {
    title: 'Confirmar Eliminación',
    data: {
      message: `¿Eliminar "${file.title}"? Esta acción no se puede deshacer.`,
      confirmText: 'Sí, eliminar',
      cancelText: 'Cancelar',
      onConfirm: () => {
        this.fileService.deleteMedia(file.id).subscribe({
          next: () => {
            this.files = this.files.filter(f => f.id !== file.id);
            this.statsChanged.emit();  // Update statistics
            this.cdr.detectChanges();
          },
          error: (error) => console.error('Error deleting:', error)
        });
      }
    }
  });
}
```

<Warning>
**Deletion is permanent!** Once confirmed, the file and all its metadata are permanently removed from the system. This action cannot be undone.
</Warning>

### Delete API Request

Files are deleted via DELETE request to `/api/files/{id}` (`front/src/services/file.service.ts:93-98`):

```typescript
deleteMedia(id: number): Observable<{ success: boolean }> {
  return this.http.delete<{ success: boolean }>
    `${this.API}/files/${id}`,
    { headers: this.getHeaders() }
  );
}
```

### Post-Deletion

After successful deletion:
1. The file is **removed from the grid** (no page reload needed)
2. **Statistics are updated** (total files, storage used)
3. The UI reflects changes immediately

## Permission-Based UI

Action buttons are conditionally rendered based on user permissions (`front/src/components/file-card/file-card.component.ts:139-147`):

```typescript
this.auth.refreshUserRole().subscribe(user => {
  this.canViewPath = !!user?.permissions?.canUpload;
  this.canDownloadContent = !!user?.permissions?.canDownload;
  this.canEditContent = !!user?.permissions?.canEdit;
  this.canDeleteContent = !!user?.permissions?.canDelete;
  
  this.cdr.markForCheck();
});
```

## Date Formatting

Dates are formatted using the browser's locale (`front/src/components/file-card/file-card.component.ts:179-183`):

```typescript
formatDate(dateStr?: string) {
  if (!dateStr) return 'N/A';
  const date = new Date(dateStr);
  return date.toLocaleDateString() + ' ' + date.toLocaleTimeString();
}
```

Example output: `3/9/2026 2:30:45 PM`

## File Type Detection

The system detects file types by extension (`front/src/services/file.service.ts:158-177`):

```typescript
getType(filename: string): 'video' | 'image' | 'audio' | 'document' | 'other' {
  const ext = filename.split('.').pop()?.toLowerCase();
  
  const videoExt = new Set(['mp4', 'webm', 'mov', 'avi', 'mkv']);
  const imageExt = new Set(['jpg', 'jpeg', 'png', 'gif', 'webp', 'bmp', 'svg']);
  const audioExt = new Set(['mp3', 'wav', 'ogg', 'flac', 'm4a']);
  const documentExt = new Set(['pdf', 'doc', 'docx', 'xls', 'xlsx', ...]);
  
  if (videoExt.has(ext)) return 'video';
  if (imageExt.has(ext)) return 'image';
  if (audioExt.has(ext)) return 'audio';
  if (documentExt.has(ext)) return 'document';
  
  return 'other';
}
```

## Troubleshooting

### Cannot Download Files

- **Cause**: Missing `canDownload` permission
- **Solution**: Contact administrator to verify your role permissions

### Cannot Edit Media

- **Cause**: Missing `canEdit` permission (Viewer role)
- **Solution**: Request an upgrade to Moderator or Admin role

### Cannot Delete Files

- **Cause**: Missing `canDelete` permission (Viewer role)
- **Solution**: Only Moderators and Admins can delete files

### Thumbnail Not Loading

- **Possible causes**:
  - Server error generating thumbnail
  - File was moved or deleted
  - Network connectivity issue
- **Solution**: Refresh the page; if issue persists, contact administrator

### Edit Modal Shows Old Data

- **Cause**: Browser cache issue
- **Solution**: Hard refresh the page (Ctrl+Shift+R or Cmd+Shift+R)

### Delete Confirmation Not Appearing

- **Cause**: JavaScript error or modal service issue
- **Solution**: Check browser console for errors and refresh the page

## Best Practices

- **Always confirm before deleting** - Deletion is permanent
- **Keep metadata updated** - Edit titles, descriptions, and tags regularly
- **Use descriptive titles** - Make files easy to identify
- **Tag consistently** - Use standard tags across similar content
- **Download before editing** - Keep backups of important files
- **Check permissions** - Verify you have the necessary role before attempting actions
